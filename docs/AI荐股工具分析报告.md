## 二、工具详细分析

### 2.1 市场数据类工具

#### QueryStockPriceInfo - 实时股价查询

**功能描述:** 批量获取多只股票的实时价格数据

**参数定义:**
```go
type Params struct {
    stockCodes string  // 股票代码，多个用逗号隔开
                 // 格式：sz399001,sh600859
}
```

**返回数据:**
```json
{
    "Code": "sz000001",
    "Name": "平安银行",
    "Price": "12.56",
    "Open": "12.50",
    "High": "12.68",
    "Low": "12.45",
    "Volume": "12345678",
    "Amount": "156789012"
}
```

**实现特点:**
- ✅ 支持批量查询（多只股票同时查询）
- ✅ 自动股票代码格式转换（600000 → sh600000）
- ✅ 实时数据，时效性强
- ✅ 包含完整的量价信息

**应用场景:**
- 实时监控多只股票价格
- 投资组合实时估值
- 价格预警触发

---

#### StockKLineData - K线数据查询

**功能描述:** 获取股票的历史K线数据（日K/周K/月K）

**参数定义:**
```go
type Params struct {
    stockCode string  // 股票代码
    period    string  // 周期: 240(日K), 60(60分), 15(15分)
    days      int     // 查询天数
}
```

**返回数据:**
```json
{
    "Day": "2026-03-04",
    "Open": 12.50,
    "High": 12.68,
    "Low": 12.45,
    "Close": 12.56,
    "Volume": "12345678"
}
```

**实现特点:**
- ✅ 支持多种周期（日K/60分/15分）
- ✅ 支持自定义查询天数
- ✅ 包含OHLCV完整数据
- ✅ 可用于技术分析

**应用场景:**
- 技术形态分析
- 指标计算（MACD/KDJ/RSI）
- 回测验证

## 三、工具架构设计

### 3.1 工具接口定义

所有工具都实现了统一的接口：

```go
type InvokableTool interface {
    // 获取工具信息（名称、描述、参数定义）
    Info(ctx context.Context) (*schema.ToolInfo, error)
    
    // 执行工具调用
    InvokableRun(ctx context.Context, argumentsInJSON string, opts ...tool.Option) (string, error)
}
```

### 3.2 参数定义模式

每个工具都通过 `schema.NewParamsOneOfByParams` 定义参数：

```go
ParamsOneOf: schema.NewParamsOneOfByParams(map[string]*schema.ParameterInfo{
    "stockCodes": {
        Type:     "string",
        Desc:     "股票代码,多个,隔开",
        Required: true,
    },
}),
```

### 3.3 数据流向

```
LLM 请求 (JSON 参数)
    ↓
工具解析 JSON 参数
    ↓
调用 data 层 API
    ↓
获取原始数据
    ↓
序列化为 JSON
    ↓
返回给 LLM
```

## 四、工具设计最佳实践

### 4.1 优秀设计模式

✅ **单一职责** - 每个工具只做一件事  
✅ **参数明确** - 清晰的参数定义和描述  
✅ **批量支持** - 支持批量操作，提高效率  
✅ **格式转换** - 自动处理股票代码等格式转换  
✅ **JSON 输出** - 标准化的 JSON 格式返回  
✅ **错误处理** - 合理的错误处理和返回  

### 4.2 可借鉴的改进点

1. **参数类型丰富化**
   - 当前主要使用 string 类型
   - 可以增加 number、array、boolean 等类型

2. **返回结构标准化**
   - 定义统一的响应结构
   - 包含状态码、消息、数据

3. **分页支持**
   - 大数据量的分页查询
   - 避免单次返回过多数据

4. **缓存机制**
   - 对不常变化的数据进行缓存
   - 减少重复请求

5. **异步执行**
   - 耗时操作支持异步
   - 先返回任务 ID，再轮询结果
