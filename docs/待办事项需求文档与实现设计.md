## 3. AI荐股架构演进-多Agent

### 3.1 需求概述

将单Agent架构演进为多Agent协作架构，不同Agent担任不同专家角色，通过多轮对话提升荐股质量。

### 3.2 现有架构分析

参考文档：`docs/AI荐股多Agent架构优化方案.md`

**当前架构**：
- 单个Agent处理所有任务
- 工具调用由单个Agent决定

**目标架构**：
```
                  ┌──────────────┐
                  │  主控Agent   │
                  │ (Orchestrator)│
                  └──────┬───────┘
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   ┌────▼────┐     ┌────▼────┐    ┌─────▼─────┐
   │ 技术面  │     │ 基本面  │    │  风控     │
   │  Agent  │     │  Agent  │    │  Agent    │
   └────┬────┘     └────┬────┘    └─────┬─────┘
        │                 │                │
        └────────────────┼────────────────┘
                         │
                  ┌──────▼───────┐
                  │  汇总Agent   │
                  │ (Synthesizer)│
                  └──────────────┘
```

---

### 3.3 Agent角色定义

| Agent名称 | 角色 | 专业领域 | 输出 |
|----------|------|----------|------|
| 主控Agent | 任务分解、协调 | 整体把控 | 任务分配、结果汇总 |
| 技术面Agent | 技术分析专家 | K线、指标、形态 | 技术面分析报告 |
| 基本面Agent | 基本面分析专家 | 财务、估值、行业 | 基本面分析报告 |
| 风控Agent | 风险控制专家 | 风险识别、仓位管理 | 风险评估报告 |
| 汇总Agent | 结果合成 | 综合判断 | 最终荐股报告 |

---

### 3.4 实现方案

#### 3.4.1 基于Eino框架的多Agent实现

参考文档：`docs/多Agent系统Phase3增强优化指南.md`

**核心组件**：

```go
// backend/agent/orchestrator/agent_interface.go - 已存在

// 定义Agent接口
type Agent interface {
    Name() string
    Role() string
    Process(ctx context.Context, input string) (*AgentResponse, error)
}

// Agent消息
type AgentMessage struct {
    From      string
    To        string
    Content   string
    Timestamp time.Time
}

// 协调器状态
type OrchestratorState struct {
    Phase           string // "decomposing" | "analyzing" | "synthesizing" | "complete"
    CurrentAgent    string
    Messages        []AgentMessage
    PartialResults  map[string]interface{}
}
```

#### 3.4.2 Harness思想多轮对话

**对话流程**：

```
1. 用户请求
   ↓
2. 主控Agent接收，分解任务
   ↓
3. 并行调用：技术面Agent、基本面Agent、风控Agent
   ↓
4. 各Agent返回初步分析
   ↓
5. 主控Agent评估，判断是否需要补充分析
   ├─ 需要 → 发送追问给相应Agent，返回步骤4
   └─ 不需要 → 继续
   ↓
6. 汇总Agent合成最终报告
   ↓
7. 返回给用户
```

**实现代码结构**：
```
backend/agent/orchestrator/
├── agent_interface.go      # Agent接口定义
├── orchestrator.go         # 主控协调器
├── technical_agent.go      # 技术面Agent
├── fundamental_agent.go    # 基本面Agent
├── risk_agent.go           # 风控Agent
└── synthesizer_agent.go    # 汇总Agent
```
